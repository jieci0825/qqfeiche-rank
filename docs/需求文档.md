# QQ 飞车手游国服记录榜 · 需求文档

> 文档版本：v0.1  
> 更新日期：2026-11-09  
> 状态：待评审  
> 关联文档：[数据模型](./数据模型.md) · [核心流程](./核心流程.md)

## 1. 背景

《QQ 飞车手游》每张赛道都有当前全服最快成绩，也就是“国服记录”。记录并不总是长期有效：某条成绩可能是利用游戏漏洞、卡复位等方式跑出来的，官方修复后这条成绩作废，榜单需要回退到它之前的上一条有效成绩。

如果用表格维护，通常只能保留“最快成绩”一个字段，作废时直接覆盖，导致：

- 看不到记录被谁、在何时、以什么原因作废；
- 回退后无法说明“之前其实是这个成绩”；
- 截图、视频、车手、车队等证据分散；
- 赛道分类维度多，筛选和统计困难。

本项目要把它做成一个可长期维护的榜单：**每张图始终只有一条当前国服记录，同时保留完整的记录沿革。**

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标 |
| --- | --- |
| G-01 | 一张赛道维护一条当前国服记录，展示成绩、车手、车队、截图、视频 |
| G-02 | 记录只增不删，作废、回退、恢复都有完整历史 |
| G-03 | 当前记录被作废后，自动回退到上一条有效成绩 |
| G-04 | 赛道按多个维度分类，可组合筛选、搜索 |
| G-05 | 提供轻量管理后台，支持手动录入与作废 |
| G-06 | 所有管理操作可追溯，能回答“谁在什么时候改了什么” |

### 2.2 非目标（v1 不做）

- 不自动抓取官方榜单、视频平台或游戏内数据；
- 不做竞速 / 道具双榜，一张图只有一条国服记录；
- 不做多人注册、角色权限、审核流，v1 只有单个管理员；
- 不做成绩预测、积分排名、车队联赛等衍生玩法；
- 不做视频内嵌播放，视频只保存并跳转外部地址；
- 不做物理复制成绩，回退通过“新版本指向旧成绩”实现（见 §5）。

## 3. 用户与权限

| 角色 | 权限 |
| --- | --- |
| 访客 | 浏览榜单、赛道详情、筛选与搜索；查看截图、跳转视频 |
| 管理员 | 登录后台；维护赛道、分类、车手、车队；录入成绩；作废成绩；查看操作日志 |

- v1 只有单个管理员账号，通过环境变量或初始化命令创建，不开放注册。
- 管理员登录后使用 HttpOnly Cookie 会话，默认有效期 7 天。
- 所有写接口必须登录；读接口公开。

## 4. 术语

| 术语 | 说明 |
| --- | --- |
| 赛道 / 地图 | 游戏内的一条赛道，例如“十一城” |
| 国服记录 | 某条赛道当前全服最快且仍然有效的成绩 |
| 成绩（run） | 某位车手某一次跑出的原始事实，包含成绩、达成时间、截图、视频等 |
| 榜单版本（version） | 榜单的一次提交，指向某条成绩；分为“上榜”和“恢复”两种 |
| 作废 | 认定某条成绩不再计入国服记录，属于软删除，数据保留 |
| 回退 | 当前记录作废后，用之前最近一条有效成绩生成新的当前版本 |
| 分类维度 | 赛道的分类角度，例如难度、场景、长度、地形 |
| 保持时长 | 一条记录作为当前国服持续的时间 |

## 5. 总体方案

### 5.1 成绩与榜单版本分离

把“成绩”和“榜单版本”拆成两层：

- **成绩（runs）** 是不可变的事实：谁、什么时间、跑了多少、证据是什么。作废只改成绩的状态。
- **榜单版本（record_versions）** 是榜单的提交记录：某条成绩在某个时刻成为当前国服，或者某条旧成绩被恢复为当前国服。

这样做的原因：

1. 作废针对的是“这次跑出来的成绩”，不是“榜单上的这一行”；
2. 回退时不需要复制成绩数据，避免同一成绩出现两份、统计重复；
3. 历史天然完整，任何时候都能还原榜单当时的样子。

### 5.2 当前记录的判定

一张赛道的当前国服记录 = **该赛道下 id 最大、且所指向成绩仍然有效的版本**。

```text
成绩：      A(有效)                 B(已作废)
版本：   v1(A, 上榜)  →  v2(B, 上榜)  →  v3(A, 恢复)
当前：                                      ↑
                                      v3 → A
```

上图中 B 被作废后，系统新建 v3 指向 A，当前国服回到 A。v2 保留在历史里，标注“已作废”。

### 5.3 两条时间轴

| 时间 | 含义 | 是否可改 |
| --- | --- | --- |
| 达成时间 `achieved_at` | 车手实际跑出成绩的时间 | 录入后不可改 |
| 版本时间 `created_at` | 该成绩被登记为当前国服的生效时间 | 不可改 |
| 作废时间 `voided_at` | 认定成绩无效的时间 | 不可改 |

展示时两个时间都要出现，避免把“很久以前跑出的成绩”误认为“刚刚跑出”。所有时间按 `Asia/Shanghai` 展示，数据库存 UTC。

## 6. 功能需求

优先级：P0 为 v1 必须，P1 为 v1 尽量，P2 为后续版本。

### 6.1 公开榜单（FR-01，P0）

- FR-01-01 展示所有未归档赛道，一张赛道一张卡片，分页或分批加载。
- FR-01-02 卡片展示：赛道名、分类标签、当前国服成绩、车手、车队、达成时间、当前保持时长、截图缩略图、视频图标。
- FR-01-03 无有效记录时展示“暂无国服记录”，不隐藏赛道。
- FR-01-04 默认按后台排序值排序，排序值相同时按赛道名称；支持按最近更新排序。
- FR-01-05 卡片点击进入赛道详情。
- FR-01-06 顶部提供搜索框和分类筛选入口。
- FR-01-07 响应式布局：手机单列、平板两列、桌面三列。

### 6.2 赛道详情（FR-02，P0）

- FR-02-01 顶部展示当前国服记录：大号成绩、车手、车队、达成时间、保持时长、截图、视频入口。
- FR-02-02 展示该赛道的全部分类标签。
- FR-02-03 历史时间线按版本倒序展示，每条包含：版本类型（上榜 / 恢复）、成绩、车手、车队、达成时间、生效时间、结束时间、保持时长、作废状态与原因。
- FR-02-04 作废记录以删除线或醒目标记展示，不能与有效记录混淆。
- FR-02-05 展示统计：历史记录条数、被打破次数、当前保持时长、最长保持时长（只统计有效区间）。
- FR-02-06 截图支持点击放大；视频在新标签页打开。
- FR-02-07 管理员登录后，详情页显示“录入成绩”“作废当前记录”入口。

### 6.3 分类与筛选（FR-03，P0）

- FR-03-01 分类采用“维度 + 取值”模型，不使用单一分类字段。
- FR-03-02 默认维度：
  - 难度：1 星、2 星、3 星、4 星、5 星（单选）
  - 场景：巅峰、排位、联赛（多选）
  - 长度：长图、中长图、短图（单选）
  - 地形：腾空、平地、加速（多选）
- FR-03-03 维度和取值均可在后台维护；维度可设置单选 / 多选。
- FR-03-04 一张赛道在每个维度上可以选多个取值，单选维度由界面限制为一个。
- FR-03-05 筛选逻辑：同一维度内多选取并集（OR），不同维度之间取交集（AND）。
- FR-03-06 筛选条件写入 URL 查询参数，刷新和分享后保持。
- FR-03-07 支持按赛道名、车手名、车队名搜索，搜索与筛选可叠加。
- FR-03-08 提供“清空筛选”。
- FR-03-09 分类只用于筛选和展示，不改变“一张图只有一条当前记录”的规则。

### 6.4 成绩录入（FR-04，P0）

表单字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 赛道 | 是 | 从已建赛道中选择 |
| 车手 | 是 | 搜索选择，可现场新建 |
| 车队 | 否 | 搜索选择，可现场新建；独立车手可留空 |
| 成绩 | 是 | 格式 `m:ss.SSS`，例如 `1:23.456`，保存为毫秒 |
| 达成时间 | 是 | 日期 + 时间，默认当前时间，不能晚于当前时间 |
| 记录截图 | 否 | jpg / png / webp，不超过 5MB，上传后预览 |
| 视频地址 | 否 | http / https 链接，不超过 500 字符 |
| 备注 | 否 | 不超过 500 字 |

校验规则：

- FR-04-01 成绩必须符合 `m:ss.SSS`，总时长大于 0 且小于 100 分钟。
- FR-04-02 有当前有效记录时，新成绩必须**严格更快**，否则拒绝并提示当前记录。
- FR-04-03 成绩与当前记录相同时不算打破纪录，拒绝录入。
- FR-04-04 同一赛道 + 车手 + 成绩 + 达成时间完全相同时，判定为重复录入，拒绝。
- FR-04-05 截图校验扩展名、MIME 与文件头，随机重命名后保存。
- FR-04-06 视频地址只接受 http / https。
- FR-04-07 录入成功后，在同一个事务内创建成绩、创建“上榜”版本、写审计日志。
- FR-04-08 成绩数值与达成时间录入后不可修改；录错时作废并重新录入，作废原因选“录入错误”。
- FR-04-09 车手、车队、截图、视频、备注等元数据可编辑，编辑必须写审计日志。
- FR-04-10 无当前记录时，任意合法成绩都可以录入，作为首条记录。

### 6.5 作废与自动回退（FR-05，P0）

- FR-05-01 作废入口：赛道详情的当前记录卡片、后台成绩列表。
- FR-05-02 作废必须选择原因，枚举如下：

| 值 | 展示名 | 说明 |
| --- | --- | --- |
| `bug` | 游戏漏洞 | 利用 bug 跑出的成绩 |
| `reset` | 卡复位 | 利用复位机制跑出的成绩 |
| `cheat` | 外挂 / 第三方 | 使用非法工具 |
| `boost` | 代跑 / 借号 | 非本人完成或账号共享 |
| `mistake` | 录入错误 | 成绩、车手、时间等录错 |
| `other` | 其他 | 必须填写备注 |

- FR-05-03 确认弹窗必须展示影响：作废后当前国服将回退到哪条成绩；没有可回退成绩时明确提示“将暂无当前国服”。
- FR-05-04 确认后，一个事务内完成：标记成绩作废、查找上一条有效记录、创建“恢复”版本、写审计日志。
- FR-05-05 恢复版本不复制成绩行，只指向被恢复的成绩；达成时间沿用原成绩时间。
- FR-05-06 如果上一条有效记录也不可信，管理员可以继续作废，系统继续向前回退（链式回退）。
- FR-05-07 如果作废到没有任何有效记录，榜单显示“暂无国服记录”。
- FR-05-08 作废非当前记录时，当前记录一般不变；但如果存在指向该成绩的恢复版本且它正是当前版本，则按同一规则回退。
- FR-05-09 已作废的成绩不能再次作废。
- FR-05-10 v1 不提供“撤销作废”；误操作通过重新录入正确成绩解决，历史保留。

### 6.6 车手与车队（FR-06，P1）

- FR-06-01 车手、车队为独立实体，成绩通过外键关联。
- FR-06-02 车手名、车队名全局唯一，录入时优先选择已有实体，避免错别字和重名。
- FR-06-03 车手详情页展示其当前持有的国服记录数量与列表；车队详情页同理。
- FR-06-04 车手、车队支持改名，改名写审计日志，历史成绩自动跟随。
- FR-06-05 v1 不做实体合并；重名或误建通过改名处理。

### 6.7 后台管理（FR-07，P0）

- FR-07-01 登录页：用户名 + 密码；连续 5 次失败锁定 15 分钟。
- FR-07-02 概览页：赛道数、有效记录数、车手数、车队数、已作废成绩数、最近变更。
- FR-07-03 赛道管理：新增、编辑、归档、排序；维护封面、描述、分类标签。
- FR-07-04 分类管理：新增 / 编辑维度与取值；被使用的取值不能删除，只能停用。
- FR-07-05 车手 / 车队管理：新增、改名；被成绩引用的实体不能删除。
- FR-07-06 成绩管理：按赛道、车手、状态筛选；查看详情；作废。
- FR-07-07 操作日志：按操作人、动作、时间筛选，只读。
- FR-07-08 未登录访问后台路由时跳转登录页；接口返回 401。
- FR-07-09 登录、登出、所有写操作都记录审计日志。

### 6.8 最近变更（FR-08，P1）

- FR-08-01 首页或独立页面展示最近 20 条榜单事件：新纪录、作废、恢复。
- FR-08-02 每条事件展示赛道、成绩、车手、事件类型、时间、操作人。
- FR-08-03 点击跳转到对应赛道详情。

### 6.9 操作日志（FR-09，P1）

- FR-09-01 记录字段：操作人、动作、实体类型、实体 ID、变更详情（JSON）、IP、时间。
- FR-09-02 动作至少包括：登录、登出、新增/编辑赛道、新增/编辑分类、新增/改名车手与车队、录入成绩、编辑成绩元数据、作废成绩（自动回退结果记录在同一日志详情中）。
- FR-09-03 日志只增不改，不提供删除入口。

### 6.10 分享与导出（FR-10，P2）

- FR-10-01 榜单筛选条件可通过 URL 分享。
- FR-10-02 后续支持 CSV 导出赛道与当前记录。
- v1 不实现导出。

## 7. 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-01 | 每条赛道最多一个当前版本；当前版本 = 该赛道 id 最大且指向有效成绩的版本 |
| BR-02 | 成绩、版本、日志不做物理删除；赛道可归档；被引用的车手、车队、标签取值不可删除 |
| BR-03 | 回退取“被作废版本之前最近一条有效版本”；不存在时当前记录为空 |
| BR-04 | 恢复版本指向旧成绩，不复制成绩行；界面呈现为一条新的“恢复”记录 |
| BR-05 | 有当前记录时，只接受严格更快的成绩；无当前记录时不限制 |
| BR-06 | 成绩相同不算打破纪录，拒绝录入 |
| BR-07 | 作废成绩后，所有指向该成绩的版本失效；若最新版本因此失效，自动创建恢复版本；作废历史成绩通常不影响当前记录 |
| BR-08 | 保持时长从版本创建时间起算；作废区间标注但不计入“最长保持”统计 |
| BR-09 | 达成时间与版本时间分开存储、分开展示；时区固定 Asia/Shanghai |
| BR-10 | 所有写操作必须记录操作人、时间、动作、对象、变更详情 |
| BR-11 | 赛道名、车手名、车队名全局唯一；标签取值在维度内唯一 |
| BR-12 | 归档赛道不出现在公开榜单，但详情和历史保留，可直接访问 |
| BR-13 | 管理员只能通过登录会话操作，公开接口只读 |
| BR-14 | 一条成绩只属于一条赛道；跨赛道成绩不合并、不比较 |

## 10. 非功能需求

技术栈：Vue 3 + Vite（前端 SPA）、Fastify（API）、SQLite（WAL）、Node.js。前后端同仓库，构建后由 Fastify 托管静态资源与上传目录，部署为单个 Node 进程。

| 编号 | 要求 |
| --- | --- |
| NFR-01 | 300 条赛道、1 万条成绩规模下，榜单首屏接口响应不超过 500ms（本地） |
| NFR-02 | 支持 360px 及以上宽度，手机可完成浏览与筛选 |
| NFR-03 | 密码使用 scrypt 哈希；会话 Cookie 设置 HttpOnly、SameSite=Lax |
| NFR-04 | 写接口校验 Origin，防止 CSRF；登录接口限流 |
| NFR-05 | 上传文件限制类型与 5MB 大小，随机文件名，禁止路径穿越 |
| NFR-06 | SQLite 开启 WAL 与外键约束；每日备份数据库与 uploads 目录 |
| NFR-07 | 所有 SQL 使用参数化查询；所有用户输入在输出时转义；视频地址只允许 http / https |
| NFR-08 | 时间统一存 UTC，展示统一 Asia/Shanghai |
| NFR-09 | 支持最新版 Chrome、Edge、Safari；不要求 IE |
| NFR-10 | 关键操作有明确成功 / 失败提示，失败不产生半成品数据 |

## 11. 验收标准

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| AC-01 | 首次录入某赛道 1:30.000 | 榜单显示该成绩为当前国服；历史有 1 条“上榜”版本；保持时长从录入时刻起算 |
| AC-02 | 当前 1:30.000，录入 1:28.000 | 当前变为 1:28.000；旧版本标记为历史；历史共 2 条 |
| AC-03 | 将 1:28.000 以“卡复位”作废 | 1:28.000 标记作废；自动生成指向 1:30.000 的“恢复”版本；当前回到 1:30.000；历史展示作废与恢复 |
| AC-04 | 继续将 1:30.000 作废 | 当前显示“暂无国服记录”；历史保留两条作废、一条恢复 |
| AC-05 | 首条记录直接作废 | 当前为空；不生成恢复版本；提示无可回退 |
| AC-06 | 当前 1:30.000，录入 1:31.000 或 1:30.000 | 均拒绝；提示必须快于当前记录；不产生任何数据 |
| AC-07 | 筛选“5 星 + 巅峰 + 长图” | 只显示同时满足三个维度的赛道；同维度多选取并集 |
| AC-08 | 未登录直接调用写接口 | 返回 401；后台页面跳转登录 |
| AC-09 | 作废、录入、改名 | 操作日志均记录操作人、时间、对象与变更详情 |
| AC-10 | 上传截图、填写视频地址 | 详情页可放大截图，视频链接可跳转 |
| AC-11 | 恢复后查看保持时长 | 恢复版本从恢复时刻重新计时，不继承被作废记录的保持时长 |
| AC-12 | 归档赛道 | 公开榜单不再展示；直接访问详情仍可查看历史 |

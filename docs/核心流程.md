# QQ 飞车手游国服记录榜 · 核心流程

> 文档版本：v0.1  
> 更新日期：2026-11-09  
> 关联文档：[需求文档](./需求文档.md) · [数据模型](./数据模型.md)

本文用具体例子说明“录入 → 上榜 → 被打破 → 作废 → 回退”的完整过程，以及各种边界情况。所有例子中的赛道、车手、车队均为虚构。

## 1. 角色与入口

| 操作 | 入口 | 权限 |
| --- | --- | --- |
| 浏览榜单、筛选、搜索 | `/` | 公开 |
| 查看赛道当前记录与历史 | `/tracks/:id` | 公开 |
| 录入成绩 | `/admin/records/new` | 管理员 |
| 作废成绩 | `/admin/records` | 管理员 |
| 维护赛道 / 分类 / 车手 / 车队 | `/admin/*` | 管理员 |
| 查看操作日志 | `/admin/logs` | 管理员 |

## 2. 流程一：首次录入

赛道“十一城”还没有任何记录。

1. 管理员进入录入页，选择赛道“十一城”。
2. 选择车手“甲”、车队“车队 A”。
3. 输入成绩 `1:30.000`，达成时间 `2026-11-01 10:00`。
4. 上传结算截图，填写视频地址（可选）。
5. 提交。

服务端处理：

```text
BEGIN IMMEDIATE
  校验成绩格式：1:30.000 → 90000ms
  查询当前记录：无
  校验重复：无
  INSERT runs            → r1（valid，90000ms）
  INSERT record_versions → v1（kind=set，run=r1，previous=NULL）
  INSERT audit_logs      → run.create
COMMIT
```

结果：

- 榜单“十一城”显示 `1:30.000`，车手“甲”，车队“车队 A”。
- 详情历史只有一条：`v1 上榜`。
- 保持时长从 `v1.created_at` 开始计算。

## 3. 流程二：正常打破记录

当前记录是 `1:30.000`。

1. 管理员录入车手“乙”、车队“车队 B”、成绩 `1:28.000`，达成时间 `2026-11-03 21:00`。
2. 服务端查询当前记录 `90000ms`，新成绩 `88000ms`，严格更快，通过。
3. 创建成绩 `r2` 和版本 `v2`（`kind=set`，`previous=v1`）。

结果：

- 当前记录变为 `1:28.000`。
- `v1` 成为历史版本，结束时间为 `v2.created_at`。
- 历史共两条，倒序展示。

数据状态：

| 成绩 | 成绩值 | 状态 | 版本 | 版本类型 | 生效时间 |
| --- | --- | --- | --- | --- | --- |
| r1 | 1:30.000 | valid | v1 | set | 11-01 10:05 |
| r2 | 1:28.000 | valid | v2 | set | 11-03 21:10 |

## 4. 流程三：作废当前记录并自动回退

两天后，官方修复了卡复位漏洞，`1:28.000` 被判定作废。

1. 管理员在后台成绩列表中点击“作废记录”。
2. 选择原因“卡复位”，填写备注“利用复位穿墙，官方 11-05 修复”。
3. 弹窗提示影响：“作废后当前国服将回退为 甲 · 1:30.000（2026-11-01）”。
4. 确认。

服务端处理：

```text
BEGIN IMMEDIATE
  锁定 r2，确认 status=valid
  UPDATE runs
    SET status='voided',
        void_reason='reset',
        void_note='利用复位穿墙，官方 11-05 修复',
        voided_at='2026-11-05T04:00:00Z',
        voided_by=1
  WHERE id=r2

  查该赛道最新版本：v2（run=r2，已失效）
  查 v2 之前最近的有效版本：v1（run=r1，valid）
  INSERT record_versions → v3（kind=restore，run=r1，previous=v2，trigger=r2）
  INSERT audit_logs      → run.void，detail 含回退目标 v3
COMMIT
```

结果：

- 当前记录回到 `1:30.000`，车手“甲”。
- 详情历史：

| 版本 | 类型 | 成绩 | 车手 | 生效时间 | 结束时间 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| v3 | 恢复 | 1:30.000 | 甲 | 11-05 12:00 | 至今 | 当前 |
| v2 | 上榜 | 1:28.000 | 乙 | 11-03 21:10 | 11-05 12:00 | 已作废（卡复位） |
| v1 | 上榜 | 1:30.000 | 甲 | 11-01 10:05 | 11-03 21:10 | 历史 |

- `v3` 的达成时间仍然是 `2026-11-01 10:00`，不是恢复时间。恢复时间只体现在 `v3.created_at`。
- `v2` 虽然被作废，但保留在历史里，能看到它曾经把纪录提高到 `1:28.000`。

### 4.1 为什么恢复版本不复制成绩

如果回退时把 `r1` 复制成一条新成绩 `r1'`：

- 同一车手、同一成绩会出现两条记录，统计“甲有几张国服”时重复计数；
- 截图、视频等证据要再复制一份，容易出现不一致；
- 后续再作废、再恢复会不断产生副本。

因此采用“新版本指向旧成绩”的方式。界面上仍然会显示成一条独立的“恢复记录”，视觉效果与复制一致，但底层只有一份成绩事实。

## 5. 流程四：链式回退

有时上一条记录也是漏洞期间跑出来的，需要继续往前回退。

初始状态：

| 成绩 | 成绩值 | 状态 | 版本 |
| --- | --- | --- | --- |
| r1 | 1:30.000 | valid | v1 set |
| r2 | 1:28.000 | valid | v2 set |
| r3 | 1:27.000 | valid | v3 set（当前） |

操作一：作废 `r3`。

- 最新版本 `v3` 失效；
- 之前最近的有效版本是 `v2`；
- 创建 `v4`（restore，run=r2，trigger=r3）；
- 当前记录变为 `1:28.000`。

操作二：继续作废 `r2`。

- 最新版本 `v4` 指向 `r2`，失效；
- 在 `v4` 之前找有效版本：`v3` 指向 `r3` 已失效，跳过；`v2` 指向 `r2` 已失效，跳过；`v1` 指向 `r1` 有效；
- 创建 `v5`（restore，run=r1，previous=v4，trigger=r2）；
- 当前记录变为 `1:30.000`。

操作三：再作废 `r1`。

- 最新版本 `v5` 失效；
- 之前没有有效版本；
- 不创建恢复版本；
- 当前记录为空，榜单显示“暂无国服记录”。

历史仍然完整保留 `v1` 到 `v5` 的全部记录和作废原因。

## 6. 流程五：首条记录作废，无可回退

赛道只有一条记录 `r1 1:30.000`。

1. 管理员作废 `r1`。
2. 最新版本 `v1` 失效。
3. 之前没有有效版本。
4. 不创建恢复版本。

结果：

- 当前记录为空。
- 详情页显示“暂无国服记录”，但仍展示 `v1` 的作废历史。
- 此时录入任意合法成绩都可以成为新的当前记录，**不再要求比 1:30.000 更快**，因为已经不存在有效记录。

## 7. 流程六：作废历史记录与级联

### 7.1 作废非当前的历史成绩

初始状态：

| 成绩 | 成绩值 | 状态 | 版本 |
| --- | --- | --- | --- |
| r1 | 1:30.000 | valid | v1 set |
| r2 | 1:28.000 | valid | v2 set |
| r3 | 1:27.000 | valid | v3 set（当前） |

后来发现 `r2` 是卡 bug 跑出来的，但它已经被 `r3` 打破，不是当前记录。

1. 管理员作废 `r2`。
2. 最新版本是 `v3`，指向 `r3`，仍然有效。
3. 当前记录保持 `1:27.000`，不创建恢复版本。
4. 历史里 `v2` 标记为已作废，`v3` 不受影响。

### 7.2 作废被恢复引用的成绩

初始状态：

| 成绩 | 成绩值 | 状态 | 版本 |
| --- | --- | --- | --- |
| r1 | 1:30.000 | valid | v1 set |
| r2 | 1:28.000 | voided | v2 set |
| r1 | 1:30.000 | valid | v3 restore（当前，指向 r1，trigger=r2） |

此时 `r2` 已经作废，`v3` 是恢复版本。如果后来发现 `r1` 也是同一漏洞期间跑的，继续作废 `r1`：

1. 最新版本 `v3` 指向 `r1`，失效。
2. 在 `v3` 之前找有效版本：`v2` 指向 `r2` 已失效，`v1` 指向 `r1` 已失效。
3. 没有有效版本，不创建恢复版本。
4. 当前记录为空。

**规则**：作废某个成绩后，所有指向它的版本都失效；系统检查“最新版本是否失效”，而不是只检查“被作废的是不是当前成绩”。这样历史成绩的作废也能正确级联。

## 8. 流程七：录入校验与平局

当前记录 `1:30.000`。

| 输入 | 结果 | 原因 |
| --- | --- | --- |
| `1:29.999` | 接受 | 严格更快 |
| `1:30.000` | 拒绝 | 相同不算打破纪录 |
| `1:31.000` | 拒绝 | 比当前慢 |
| `abc` | 拒绝 | 格式错误 |
| `1:60.000` | 拒绝 | 秒数非法 |
| `0:00.000` | 拒绝 | 必须大于 0 |
| `100:00.000` | 拒绝 | 超过 100 分钟上限 |
| 同赛道 + 同车手 + 同成绩 + 同达成时间 | 拒绝 | 重复录入 |

- 有多条历史但当前为空时，只和“当前有效记录”比较；没有当前记录就不限制快慢。
- 拒绝时不产生成绩、版本、日志（失败原因可记录在应用日志，不写业务审计）。

成绩格式转换：

```text
1:23.456 → 1 × 60000 + 23 × 1000 + 456 = 83456ms
0:59.999 → 59999ms
10:00.000 → 600000ms
```

展示时反向格式化为 `m:ss.SSS`，分钟不补零，秒和毫秒补零。

## 9. 流程八：保持时长与历史统计

### 9.1 定义

| 项 | 计算方式 |
| --- | --- |
| 生效时间 | 版本 `created_at`，即上榜或被恢复的时间 |
| 结束时间 | 下一条版本的 `created_at`；没有下一条时，已作废取 `voided_at`，否则取当前时间 |
| 保持时长 | 结束时间 − 生效时间 |
| 有效保持 | 只统计成绩 `status=valid` 的区间；已作废区间展示但不计入“最长保持” |
| 当前保持 | 当前版本 `created_at` 至今 |

保持时长从**上榜时间**起算，不是从达成时间起算。这样补录一条很久以前跑出的成绩时，不会把“当时还没登记”的时间算进去。

### 9.2 例子

接流程三：

| 版本 | 生效 | 结束 | 时长 | 是否计入最长保持 |
| --- | --- | --- | --- | --- |
| v1 | 11-01 10:05 | 11-03 21:10 | 2 天 11 小时 | 是 |
| v2 | 11-03 21:10 | 11-05 12:00 | 1 天 15 小时 | 否（已作废） |
| v3 | 11-05 12:00 | 至今 | 持续累计 | 是 |

- “被打破次数”只统计有效成绩被更快成绩替代的次数，作废不算“被打破”。
- “历史记录条数”包含作废记录，用于展示完整沿革。
- 恢复版本会重新开始计时，不继承被作废记录的保持时长。

## 10. 完整数据走查

以流程三结束后的状态为例。

### 10.1 runs

| id | track | driver | team | time_ms | achieved_at | status | void_reason | voided_at |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| r1 | 十一城 | 甲 | 车队 A | 90000 | 11-01 10:00 | valid | NULL | NULL |
| r2 | 十一城 | 乙 | 车队 B | 88000 | 11-03 21:00 | voided | reset | 11-05 12:00 |

### 10.2 record_versions

| id | track | run | kind | previous | trigger | created_at |
| --- | --- | --- | --- | --- | --- | --- |
| v1 | 十一城 | r1 | set | NULL | NULL | 11-01 10:05 |
| v2 | 十一城 | r2 | set | v1 | NULL | 11-03 21:10 |
| v3 | 十一城 | r1 | restore | v2 | r2 | 11-05 12:00 |

### 10.3 当前记录查询

```sql
SELECT v.id, v.kind, r.id, r.time_ms, d.name
FROM record_versions v
JOIN runs r ON r.id = v.run_id
JOIN drivers d ON d.id = r.driver_id
WHERE v.track_id = 1
  AND r.status = 'valid'
ORDER BY v.id DESC
LIMIT 1;
```

结果：

```text
v3 | restore | r1 | 90000 | 甲
```

## 11. 异常与边界

| 情况 | 处理 |
| --- | --- |
| 两个管理员同时录入 | `BEGIN IMMEDIATE` 串行化，后提交者重新校验当前记录 |
| 上传成功但录入失败 | 记录孤儿文件，定时任务清理未被引用的上传文件 |
| 截图文件伪造扩展名 | 校验文件头与 MIME，不通过则拒绝 |
| 视频地址是 `javascript:` | 只允许 http / https |
| 赛道被归档 | 不再出现在公开榜单；详情可访问；录入页默认不显示 |
| 车手 / 车队被成绩引用 | 禁止删除，只允许改名 |
| 标签取值被赛道使用 | 禁止删除，只允许停用 |
| 作废时没有上一条有效记录 | 当前记录置空，不创建恢复版本 |
| 作废一个已作废成绩 | 拒绝，提示已作废 |
| 管理员会话过期 | 写接口返回 401，前端跳转登录 |
| 数据库写入冲突 | `busy_timeout` 等待后重试；仍失败则返回可读错误 |
| 最新版本指向失效成绩但没有恢复版本 | 运行数据修复检查，补恢复版本并写日志 |

## 12. 权限与审计

### 12.1 登录

1. 管理员提交用户名、密码。
2. 服务端按用户名查询，使用 scrypt 校验密码。
3. 连续 5 次失败，锁定 15 分钟。
4. 成功后签发 HttpOnly、SameSite=Lax 的会话 Cookie，默认 7 天。
5. 记录 `auth.login` 审计；失败也记录次数，但不记录明文密码。

### 12.2 写操作校验

- 所有 `POST` / `PUT` / `PATCH` / `DELETE` 接口先校验会话。
- 校验 `Origin` / `Referer` 与站点域名一致，防止 CSRF。
- 校验请求体字段类型、长度、枚举值。
- 事务失败时回滚，不留下半成品数据。

### 12.3 审计动作

| action | 触发 |
| --- | --- |
| `auth.login` / `auth.logout` | 登录、登出 |
| `track.create` / `track.update` / `track.archive` | 赛道维护 |
| `tag.create` / `tag.update` | 分类维度、取值维护 |
| `driver.create` / `driver.update` | 车手维护 |
| `team.create` / `team.update` | 车队维护 |
| `run.create` | 录入成绩 |
| `run.update_meta` | 修改车手、车队、截图、视频、备注 |
| `run.void` | 作废成绩；`detail` 内含自动回退到的版本与成绩 |
| `auth.login_failed` | 登录失败（记录用户名与 IP，不记录密码） |

审计 `detail` 建议存变更前后快照：

```json
{
  "before": { "status": "valid" },
  "after": { "status": "voided", "void_reason": "reset" },
  "restored_version_id": 3,
  "restored_run_id": 1,
  "restored_time_ms": 90000
}
```
